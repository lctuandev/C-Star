# Documentation Rules

Documentation exists to preserve project context.

Do not document every tiny implementation detail.

Document information that helps a future developer understand:

- what was changed
- why it was changed
- how it behaves
- important constraints
- known problems
- architectural decisions

---

# Update Progress

Update progress after meaningful milestones.

Do not wait until the end of a large task.

---

# Architecture

When introducing a new architectural pattern:

Create an ADR.

Location:

`.project/decisions/`

---

# Current State

Keep:

`.project/CURRENT.md`

accurate.

Do not put long historical information there.

Historical information belongs in task documentation.

---

# History

Completed tasks should preserve:

- plan
- progress
- test
- result

Do not delete completed task records.
